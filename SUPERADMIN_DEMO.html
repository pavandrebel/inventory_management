🔑 Authentication Flow

When a user tries to login, the system performs these checks in order:

1. Validate Credentials
Check email and password against database
2. Check System Lock Status
Is system_status.is_locked == true?
3. Check User Role
If system is locked:
  • ✓ SuperAdmin? → Grant full access (bypass approval)
  • ✗ Other role? → Go to Step 4
4. Check User Approval Status
Look up user_approvals table for this user
5. Grant or Deny Access
  • Status = approved: Grant token & access
  • Status = pending: Deny (waiting for superadmin)
  • Status = rejected: Deny (contact superadmin)

💡 Key Point: The system lock applies to all users EXCEPT the superadmin. This gives the superadmin complete control to grant/deny access to other users.

📡 API Endpoints

POST/api/system/lock
{ "reason": "Scheduled maintenance" }

Lock system, no one except superadmin can login

POST/api/system/unlock

Unlock system, allow approved users to login

GET/api/system/status
{ "is_locked": true, "locked_by_id": 1, "locked_reason": "Scheduled maintenance", "locked_at": "2024-01-15T10:30:00Z" }
POST/api/users/{id}/approve
{ "status": "approved" }

SuperAdmin approves a user to access the system

POST/api/users/{id}/reject
{ "reason": "Insufficient credentials" }

SuperAdmin rejects a user's access request

GET/api/users/pending-approvals

List all users waiting for approval
